## Context

### Original Request
User wants to: (1) test the language with real use cases to find hidden problems and fix them, (2) send the branch to main/master, (3) fix CI/CD in GitHub, (4) host a webpage on GitHub Pages.

### Interview Summary
**Key Discussions**:
- Branch: `main` (modern convention), retire stale `master` → `legacy-master` (reversible, NOT deleted)
- Use case scale: MIX — 15 focused examples (50-200 lines) + 3 full apps (500-2000 lines)
- Bug fix policy: FIX EVERYTHING — known bugs + bugs discovered during testing + missing features needed by use cases
- GitHub Pages: subpath strategy (vinaosb.github.io/buff/), `actions/deploy-pages@v4`, single aggregated deploy

**Research Findings**:
- 60+ existing examples (strong on language features, weak on production patterns)

- CI/CD: 5 workflows exist, branch refs inconsistent, missing Pages/CODEOWNERS/FUNDING
- Web assets: website (static), playground (needs WASM build), docs (48 error pages), book (mdBook, needs build)
- Pages: subpath strategy, .nojekyll required, WASM MIME correct, no COOP/COEP (single-threaded OK for transpile-only)

### Metis Review
**Identified Gaps** (addressed):
- AGENTS.md stale (v1.24 vs v1.38): Wave 0 refresh task added
- Branch rename blast radius (book.toml, CI, VSCode, buffup): Wave 4 string-ref sweep task added

- Pages deploy race: single aggregated deploy job (Wave 4)

- Playground is transpile-only: documented as acceptance criterion

## Work Objectives

### Core Objective
Prove Buff works for real-world programs by writing 18 use cases that exercise production patterns, fixing every bug they uncover plus known compiler bugs, then launching publicly with `main` branch, repaired CI/CD, and live GitHub Pages.

### Concrete Deliverables
- 18 new `.buff` use case files in `examples/use-cases/`
- 18 golden `.expected` files for automated testing
- Bug fixes across buff-lang-types, buff-lang-codegen-rust, buff-ml, buff-tensor
- `main` branch as default, `master` renamed to `legacy-master`
- 6-7 GitHub workflows (ci, security, release, docker, bufflings, pages, possibly bench)
- `.github/CODEOWNERS`, `.github/FUNDING.yml`
- `pages.yml` workflow deploying to GitHub Pages
- Refreshed `AGENTS.md` matching v1.38 reality

### Definition of Done
- [ ] All 18 use cases compile via `buff check` and run via `buff run` producing expected output
- [ ] `cargo test --workspace` passes (0 failures)
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` passes
- [ ] `main` is default branch on GitHub (`gh api repos/.../buff --jq .default_branch` → "main")
- [ ] `curl -fsI https://vinaosb.github.io/buff/` returns 200
- [ ] `grep -rn "v1x-frameworks" --include=*.toml --include=*.yml --include=*.md .` returns only historical changelog hits

### Must Have
- 15 focused examples covering distinct gap areas (HTTP, file I/O, DB, CLI, concurrency, data processing, auth, testing, networking, logging, crypto, graceful shutdown, error recovery, generics stress, pattern matching stress)
- 3 full apps (REST API server, CLI tool, data processing pipeline)
- Known bug fixes with regression tests
- `main` branch + ref sweep
- GitHub Pages with working playground (transpile-only), book, docs, landing
- AGENTS.md refreshed

### Must NOT Have (Guardrails)
- NO deleting `master` (rename to `legacy-master` — reversible)
- NO touching `tests/` in unreachable!() cleanup (src/ only)
- NO ErrorCode renumbering/reuse/back-filling (append-only)
- NO per-site Pages deploys (single aggregated deploy only)
- NO book chapter rewrites (add ONE new chapter only)
- NO framework crate full implementations (per-crate budget cap; use cases degrade to avoid unbounded features)
- NO deploying book without content review or "draft" banner
- NO positional boolean args, tabs, `_async` suffix (Buff language rules)
- NO `unwrap`/`expect`/`panic!`/`todo!` in non-test code (hard rule)
- NO raw-string Rust codegen (syn/quote/prettyplease only)
- NO HashMap/HashSet (BTreeMap/BTreeSet only)
- NO `[features]` section in Cargo.toml
- NO version pinning in crate Cargo.toml (workspace deps only)
