T124d: Regex module (Regex.compile + regex.match/find/replace/captures)
========================================================================

DATE: 2026-07-20
BRANCH: master
STATUS: COMPLETE — all three gates green.

WHAT WAS BUILT
-------------

First v1.4 prelude module with INSTANCE METHODS on a compiled runtime
value. DateTime (T124b) was assoc-fn + accessors only; Log (T124c) was
namespace-only. Regex is a real first-class value whose primary surface
IS the instance-method dispatch (regex.match/find/replace/captures).

Surface added:

    Regex.compile(pattern)         -> Regex           (assoc fn)
    regex.match(text)              -> Option<String>  (instance)
    regex.find(text)               -> Option<String>  (instance)
    regex.replace(text, repl)      -> String          (instance)
    regex.captures(text)           -> Map<String,String>  (instance)

The canonical acceptance criterion is met:
    regex.replace("a1b2", "\\d", "X") -> "aXbX"

   - Added registration in RustCodegen::generate:

   - Extended ast_typeref_to_syn: Regex source annotation -> syn path
     `regex::Regex`.
   - Extended buff_type_to_syn: Type::Regex -> "regex::Regex".
   - Extended buff_primitive_to_rust_name: "Regex" -> "regex::Regex".
   - Extended lower_prelude_type_assoc_fn with (Regex, Compile) arm.
     Lowering:
         regex::Regex::new(pattern)
             .unwrap_or_else(|_| regex::Regex::new(r"a^").unwrap())
     This mirrors T124b's DateTime.parse unwrap_or pattern. The inner
     .unwrap() is on the provably-valid literal `r"a^"` (an 'a' followed
     by start-of-string anchor — syntactically valid, semantically never
     matches). This is the established Rust idiom for infallible fallback
     from a fallible ctor when no const-fn constructor exists (regex has
     no Regex::empty() or const constructor; chrono's Utc::now() is the
     equivalent trusted call in the T124b precedent).
   - Extended lower_prelude_type_instance_fn with 4 arms:
     * Match:   if recv.is_match(text) { Some(text.to_string()) } else { None }
     * Find:    recv.find(text).map(|m| m.as_str().to_string())
     * Replace: recv.replace_all(text, repl).to_string()
     * Captures: { let __buff_caps = recv.captures(text);
                  let mut __buff_map: HashMap<String, String> = HashMap::new();
                  if let Some(__buff_c) = __buff_caps {
                      for (__buff_i, __buff_opt) in __buff_c.iter().enumerate() {
                          if let Some(__buff_m) = __buff_opt {
                              __buff_map.insert(__buff_i.to_string(),
                                                __buff_m.as_str().to_string());
                          }
                      }
                      for __buff_name in recv.capture_names().flatten() {
                          if let Some(__buff_m) = __buff_c.name(__buff_name) {
                              __buff_map.insert(__buff_name.to_string(),
                                                __buff_m.as_str().to_string());
                          }
                      }
                  }
                  __buff_map }
     The captures block is DETERMINISTIC at the codegen level (same AST
     -> byte-identical Rust). Numbered groups iterate in INDEX order
     (0=full match, 1=first group, ...); named groups iterate in
     source-declaration order via capture_names().flatten() (skipping
     unnamed positions). The runtime HashMap iteration order is NOT
     deterministic (Rust HashMap property), but lookups by key work
     regardless. Captures use quote! + syn::parse2 (the standard
     pattern) so the single string producer remains prettyplease.

KNOWN LIMITATIONS
-----------------

1. End-to-end link deferred (same boundary as chrono/tokio/tracing).
   Generated code uses fully-qualified `regex::Regex::...` paths and
   records `regex` in extern_crates, but the single-file `buff run`
   rustc path does NOT link the regex crate. Cargo-project wiring is
   deferred. Acceptance = snapshot-verified codegen + registry wired +
   workspace green (the standard v1.4 acceptance criterion).

2. `match` is a Buff keyword (one of the 25 reserved). The parser today
   only accepts TokenKind::Ident(_) in method-call position
   (crates/buff-lang-parser/src/expr.rs:519), so `regex.match(text)`
   will NOT parse from Buff source today. The registry + codegen still
   wire up the Match variant so:
     (a) AST-constructed tests exercise the lowering end-to-end;
     (b) a future parser relaxation (allowing keywords in method-call
         position) lights it up with NO further registry/codegen work.
   The other three instance methods (find/replace/captures) parse fine
   since they're not keywords. This is a parser limitation, NOT a
   registry/codegen limitation.

DEVIATIONS FROM T124b PRECEDENT
-------------------------------

1. Inner .unwrap() on a provably-valid literal fallback. T124b's
   DateTime.parse uses `unwrap_or(chrono::Utc::now())` — the fallback
   is an infallible function call. The regex crate has no equivalent
   infallible constructor (`Regex::new` is the only path and returns
   Result). The codegen generates
   `regex::Regex::new(r"a^").unwrap()` as the fallback — the .unwrap()
   on the provably-valid literal `r"a^"` is the minimum deviation
   needed (any other approach would require a runtime static LazyLock
   or const-fn constructor the regex crate doesn't provide).

2. New predicate Type::is_prelude_regex() (separate from
   is_prelude_datetime). T124b's predicate covers only the chrono
   family. Regex is a runtime value but NOT a datetime, so a separate
   predicate is needed. The prelude_types.rs test
   `prelude_type_lookup_known_names` was extended to skip the datetime
   round-trip check for Regex (mirroring the existing skip for
   namespace-only Log).
