## Scaffold Structure

When a user runs `buff ui new --desktop my_app`, the following tree is created:

```
my_app/
├── buff.toml              # [package] name = "my_app", [ui] frontend = "dioxus", desktop = true
├── .gitignore
├── src/
│   └── main.buff          # @ui func main(): signal(0), button with onclick, render(...)
├── src-tauri/
│   ├── Cargo.toml          # tauri 2, tauri-plugin-shell 2, serde, serde_json
│   ├── tauri.conf.json     # productName: my_app, window 1024x768, frontendDist: ../static
│   ├── build.rs            # tauri_build::build()
│   └── src/
│       ├── main.rs         # fn main() { my_app_desktop_lib::run() }
│       └── lib.rs          # tauri::Builder with greet IPC command
└── static/
    └── index.html          # HTML shell loading bundle.js
```

The scaffolded Buff source (`src/main.buff`) mirrors the T130 Dioxus counter
example: `signal(0)`, `onclick: move |_| count.set(count() + 1)`,
`"Increment (count: {count()})"`. The `@ui` attribute marks it as the UI entry
point for the compiler.

## Native-Build USER ACTION Recipe

The `buff ui build --desktop` subcommand detects whether `cargo-tauri` is
installed. If missing, it prints:

```
Tauri CLI is required to build desktop apps.
Install it with: cargo install tauri-cli
```

and exits with code 1. To produce a native desktop binary, the user must:

1. Install the Tauri CLI: `cargo install tauri-cli`
2. Install platform prerequisites (WebView2 on Windows, WebKitGTK on Linux,
   WebKit on macOS — see https://v2.tauri.app/start/prerequisites/)
3. cd into the scaffolded project: `cd my_app`
4. Build the Wasm frontend: `buff ui build --desktop`
5. Build the native binary: `cargo tauri build` (or `npx tauri build`)

The output binary is placed in `src-tauri/target/release/` by default.

## Design Decisions

- **No tauri runtime dep on buff-lang-cli**: Only the scaffold template's
  Cargo.toml references `tauri = "2"`. buff-lang-cli itself has zero tauri
  dependency (avoids pulling proton SDK / WebView2 SDK).
- **include_str! over rust-embed**: Matches the existing `scaffold.rs` pattern
  (plain string templates, no TPL engine dep). Templates live in
  `templates/desktop/` alongside the source.
- **UiCmd extension over new Command variant**: Follows the T131 pattern —
  `buff ui` is the parent subcommand, and `new`/`build` are its children.
- **`--desktop` flag**: Explicit flag (not a positional) so future targets
  (mobile, web) can be added as `--mobile` / `--web` without breaking the
  CLI shape. The flag is validated — omitting it prints a clear error.
- **Tauri 2.0 config format**: Uses the `tauri.conf.json` v2 schema
  (`app.windows[]`, `build.frontendDist`, `build.beforeDevCommand`).
  The `identifier` field uses the `com.buff-lang.{name}` convention.
