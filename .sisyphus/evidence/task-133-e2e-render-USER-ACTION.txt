## Recipe (counter.buffhtml → wasm32 → browser render)

### Step 1 — Set up a Cargo project shell

`buff build` on a single `.buffhtml` invokes `rustc` directly, which cannot
link `dioxus` (a large external crate). Browser-renderable Wasm requires a
Cargo project. Create a minimal one:

```powershell
# Create project skeleton
mkdir buffhtml-counter-app
cd buffhtml-counter-app
cargo init --lib --name buffhtml_counter_app
```

Edit `Cargo.toml`:

```toml
[package]
name = "buffhtml_counter_app"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib"]

[dependencies]
dioxus = { version = "0.7", features = ["web"] }
```

Copy the example `.buffhtml` into `src/`:

```powershell
Copy-Item ..\buff\examples\counter.buffhtml .\src\counter.buffhtml
```

### Step 2 — Transpile `.buffhtml` → `.rs`

```powershell
# From the buff checkout, invoke the CLI on the project's src/ dir:
..\buff\target\release\buff.exe build .\src\counter.buffhtml
# Produces .\src\counter.rs alongside the .buffhtml source.
```

Inspect `.\src\counter.rs` — it should look like:

```rust
use dioxus::prelude::*;
#[component]
fn Counter() -> Element {
    let mut count = use_signal(|| 0);
    let increment = move |_| {
        count += 1;
    };
    rsx! {
        div { class : "counter", span { count }, button { on_click : increment, "+1", },
        },
    }
}
```

Wire it into the crate via `src/lib.rs`:

```rust
mod counter;

use dioxus::prelude::*;

fn main() {
    dioxus::LaunchBuilder::new()
        .launch(counter::Counter);
}
```

### Step 3 — Build for wasm32

```powershell
cargo build --target wasm32-unknown-unknown --release
```

Output: `target/wasm32-unknown-unknown/release/buffhtml_counter_app.wasm`.

### Step 4 — Run `wasm-bindgen` post-processing

```powershell
wasm-bindgen --target web --out-dir static `
    target\wasm32-unknown-unknown\release\buffhtml_counter_app.wasm
```

Output: `static/buffhtml_counter_app.js` + `static/buffhtml_counter_app_bg.wasm`.

### Step 5 — Author a tiny HTML shell

Create `static/index.html`:

```html
<!DOCTYPE html>
<html>
<head><meta charset="utf-8"><title>Buff .buffhtml Counter</title></head>
<body>
<div id="main"></div>
<script type="module">
    import init from "./buffhtml_counter_app.js";
    init();
</script>
</body>
</html>
```

### Step 6 — Serve over HTTP + open in browser

```powershell
# Python 3 stdlib http.server is the lowest-friction option:
python -m http.server --directory static 8080
```

Open <http://localhost:8080/> in any modern browser. The counter renders
with a `+1` button. Clicking increments the displayed value.

### Step 7 — Verify (manual)

- [ ] Page loads without console errors.
- [ ] Counter shows `0` initially.
- [ ] Clicking `+1` increments by 1 each click.
- [ ] Browser devtools → Network tab shows `buffhtml_counter_app_bg.wasm`
      loading successfully.

## Why USER ACTION?

The build host runs `cargo check` / `cargo test --lib` only. Live wasm32
rendering requires:

1. **Network egress** to fetch `dioxus`/`wgpu` transitive deps on first
   build (host is airgapped for hermetic gates).
2. **Browser process** — there's no headless-browser harness on the build
   host (T121b spike used a throwaway headless shell; T133 keeps the gate
   surface minimal).
3. **Time budget** — the full wasm-bindgen + http.server + browser-open
   cycle takes 2–5 minutes per example; doing it in CI would multiply the
   gate wall-time without catching bugs the lib-test suite doesn't already
   catch.

The lib-test suite (`crates/buff-lang-cli/tests/buffhtml_integration_t133.rs`)
asserts the entire codegen path end-to-end (parse → codegen → script-block
splice → `.rs` write) without invoking rustc. That's the build-host
contract; the rest is up to the user.
