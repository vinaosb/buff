T131 — buff ui dev hot-reload server
=====================================

Task: Add `buff ui dev [PATH] [--port <N>]` subcommand — a Vite/trunk/cargo-leptos-style dev server that watches .buff files, rebuilds Wasm on change (debounced 200ms), and live-reloads connected browsers via WebSocket.

Architecture (chosen by the implementing agent)
-----------------------------------------------
- CLI wiring: `cli.rs` gains `Command::Ui { cmd: UiCmd }` variant (L375) + `UiCmd::Dev { path, port }` subcommand (L437, default path = cwd, default port = 8080). Dispatch in `main.rs`: `Command::Ui { cmd } => buff_lang_cli::commands::ui_dev::run(cmd)`. `commands/mod.rs` declares `pub mod ui_dev;`.
- Server library lives under `crates/buff-lang-cli/src/ui_dev/` (7 files, ~80 KB):
  - `mod.rs`        — public entry `serve()`, `run()`, rebuild loop orchestration
  - `broadcaster.rs` — `Broadcaster` multi-subscriber WebSocket fan-out (tokio::sync::broadcast), JSON message envelope `{type:"reload"}` / `{type:"error",message:"..."}`
  - `builder.rs`     — rebuild pipeline: Buff front-end (`pipeline::compile_to_rust`) + `cargo build --target wasm32-unknown-unknown` + `wasm-bindgen --target web`; `find_freshest_wasm` helper
  - `watcher.rs`     — `notify` 6.x RecommendedWatcher + 200ms tokio debounce buffer
  - `http.rs`        — axum 0.8 router: static files from `<path>/static/`, wasm fallback from `<path>/target/wasm32-unknown-unknown/<profile>/`, `/__buff_reload__` WebSocket upgrade, HTML injection of client JS
  - `client_js.rs`   — <1 KB compile-time `&str` snippet: opens WS, listens for reload/error, calls `location.reload()` on reload, shows red overlay on error + "Reconnect" button, shows "Dev server disconnected" on close
  - `error.rs`       — thiserror Error enum for dev-server failures
- `commands/ui_dev.rs` — thin CLI adapter (clap UiCmd -> ui_dev::serve()).
- HTTP framework: axum 0.8 (workspace dep, `ws` feature enabled). WebSocket via `axum::extract::ws::WebSocketUpgrade` — NO separate tokio-tungstenite direct dep needed.
- File watcher: notify 6.x (workspace dep, major-version pin; pure-Rust on Win/Linux/macOS, no native C dep, matches the "no C library" hard rule). 200ms debounce implemented in-tree via `tokio::time::sleep` buffer — `notify-debouncer-mini` deliberately NOT pulled (minimal dep surface).
- futures-util (already workspace-pinned from T124m) provides SinkExt/StreamExt for the WS split.
- tower (workspace, dev-dep) used in unit tests via `ServiceExt::oneshot` to drive the Router in-process (mirrors buff-registry test pattern) — NO TCP bind in tests.
- tokio gains `test-util` feature (for `tokio::time::pause` in debounce tests).
