ITEM 2 — Component interface declaration
----------------------------------------
CHOSEN SYNTAX: `<script lang="buff" props="Props">` (option a from
the task spec). Rationale documented in docs/component-model.md §2:
reuses Rust struct syntax, self-documenting attribute, backward-
compat with T133 floor (no `props` → existing const+empty-arg path).

Plumbing changes:
- AST (buff-lang-ast-rsx): ScriptBlock gains `props: Option<String>`
  field + `with_props(...)` constructor. Backward-compatible via
  updated `new(...)` (defaults props=None).
- Lexer (buff-lang-buffhtml-parser): ScriptOpen token extended to
  `{ lang, props }`. `scan_script_attrs()` returns `(String,
  Option<String>)`. Unknown attributes silently ignored (forward-
  compat). 2 new lexer unit tests cover the props-capture path.
- Parser: `parse_template` reads both fields from ScriptOpen and
  selects `ScriptBlock::with_props` vs `::new` accordingly.
- Codegen (buff-lang-codegen-buffhtml): `build_file_items` extended
  to the typed-props path:
    1. parse_script_block(source) — wraps script in `{...}` and
       parses as syn::Block, partitioning into `module_items`
       (Stmt::Item) vs `body_stmts` (Stmt::Local / Stmt::Expr).
    2. extract_props_interface(parsed, name) — finds the named
       Item::Struct and reads its field idents.
    3. Auto-generates `let <Type> { f1, f2, .. } = props;` as the
       FIRST body statement (empty-fields fallback emits
       `let <Type> { .. } = props;` so a missing-struct case still
       surfaces a clean rustc diagnostic).
    4. Switches signature to `fn <Name>(props: <Type>) -> Element`.

Backward compat preserved: when `props` is absent, the existing
T133-floor path runs unchanged (`const __BUFF_SCRIPT_SOURCE` +
zero-arg fn). The 2 existing T133 tests asserting on
`__BUFF_SCRIPT_SOURCE` still pass.

6 new codegen tests in tests/codegen_tests.rs cover: no-props floor
preserved, props signature generation, struct hoisted to module
scope, destructure lists every field, body statements spliced in
correct order (destructure < body < rsx!), and missing-struct
fall-through.

ITEM 3 — Prop type pre-checker (buff-lang-codegen-buffhtml)
-----------------------------------------------------------
NEW MODULE: src/prop_check.rs (~750 lines including tests).

Public API:
- PropField { name, type_name, required: bool } — every declared
  field is treated as required for T134 (Option<T> opt-out is T135+).
- ComponentInterface { tag_name, struct_name, fields }
- PropInterfaceRegistry — HashMap<tag_name, ComponentInterface>
  with register/lookup/len/is_empty.
- PropCheckKind { MissingRequired, UnknownProp, TypeMismatch }
- PropCheckDiagnostic { kind, message, span }
- extract_interface(template, tag_name) -> Option<ComponentInterface>
  — reuses the same struct-parsing logic as codegen (wrapped in
  `{...}`, parsed as syn::Block, walks for Item::Struct matching
  the declared name). Returns None when no script, no props attr,
  or named struct absent (caller skips).
- check_props(parent_template, &registry) -> Vec<PropCheckDiagnostic>
  — walks the tree depth-first, source-order. For each component
  invocation:
    * If the component isn't in the registry → SKIP (backward-compat
      with T133 floor components).
    * If `{...spread}` is present → SKIP all checks (can't know
      contents statically).
    * Missing-required: one diagnostic per missing required field.
    * Unknown-prop: one diagnostic per provided-but-undeclared prop
      (carries the OFFENDING ATTRIBUTE's span, not the tag span).
    * Stretch literal-type matching: classify_literal(value)
      detects String/Integer/Boolean literals; type_mismatch(lit,
      declared) returns Some(description) for obvious mismatches
      (e.g. "42" vs String → "integer"; "five" vs i32 → "string").
      Non-literal values (identifiers, calls) are skipped.

Spans are attached directly to each diagnostic — the existing
SpanMap infrastructure from T133 (SpanMapBuilder + SpanMap::map_span)
lets the CLI render them as .buffhtml file:line:col positions.

22 new unit tests cover: extract_interface (4 cases), classify_literal
(4), type_mismatch (4), check_props end-to-end (8 — including
no-interface skip, missing-required count, unknown-prop span,
all-required-clean, type mismatch both directions, spread bypass,
nested-element+if traversal, event-handler-not-a-prop), registry (2).

4. CHOSEN INTERFACE-DECLARATION SYNTAX + RATIONALE
================================================================

SYNTAX: `<script lang="buff" props="TypeName">` (option a).

Considered alternatives (per task spec):
- (a) `props=` attribute on <script> ✅ CHOSEN
- (b) `{#props count: Int, name: String}` directive
- (c) convention: auto-derive from `struct Props` in script body

WHY (a):
1. Reuses Rust struct syntax (no new parser surface for field lists).
2. Self-documenting attribute name — `grep -r 'props="'` finds every
   typed-prop component in a codebase.
3. Backward-compatible with T133 floor: no `props` attribute → existing
   `const __BUFF_SCRIPT_SOURCE` + zero-arg fn path is unchanged.
4. Forward-compatible: the attribute carries a TYPE NAME, not a field
   list, so users can later point at any struct (not just `Props`) —
   including ones imported from other modules.
5. Synergistic with the prop type pre-checker (item 3): the same
   `extract_interface` function walks both directions (codegen reads
   the struct for the destructure; pre-checker reads it for field
   validation).

5. LIFECYCLE HOOK → DIOXUS MAPPING
================================================================

| Buff helper           | Dioxus 0.7 backing API | When it fires            |
|-----------------------|------------------------|--------------------------|
| on_init(\|\| { ... })  | use_effect (wrapped)   | Once after mount         |
| on_destroy(\|\| { ... })| use_drop              | Once on unmount          |

`use_effect` natively accepts FnMut + reruns on tracked-signal
changes. The on_init wrapper drains an Option<F> on the first call,
making subsequent reruns a no-op — guaranteeing the user's closure
fires exactly once even if the effect re-runs before unmount.

`use_drop` is Dioxus 0.7's canonical unmount hook (lives in
dioxus-core/src/global_context.rs, re-exported via
dioxus::prelude::use_drop and dioxus-hooks::use_drop). It implements
Drop on a guard attached to the current scope — the closure fires
when the scope tears down.

Dioxus version pinning: workspace Cargo.toml has `dioxus = "0.7"`
(caret pin per T130 decision record). Verified locally against the
dioxus-0.7.9 source tree at
~/.cargo/registry/src/index.crates.io-*/dioxus-{core,hooks}-0.7.9/.

6. PROP PRE-CHECKER ARCHITECTURE
================================================================

The pre-checker is a new module (`src/prop_check.rs`) inside
buff-lang-codegen-buffhtml. It runs AFTER parse + codegen, BEFORE
rustc. Pipeline:

  .buffhtml source
      │
      ▼ parse
  RsxTemplateFile (AST)
      │
      ├──▶ extract_interface ──▶ ComponentInterface
      │                          (per-file, run by CLI)
      │
      ▼ registry build
  PropInterfaceRegistry (HashMap<tag_name, ComponentInterface>)
      │
      ▼ check_props(parent_template, &registry)
  Vec<PropCheckDiagnostic>
      │
      ▼ CLI error_mapper
  Rendered .buffhtml-span diagnostics (uses existing SpanMap)

Backward compatibility:
- Components with no `props=` attribute are SKIPPED by the checker
  (registry lookup misses → return early).
- Spread props (`{...rest}`) cause the entire invocation to SKIP
  (can't statically inspect rest's contents).
- Event handlers (`on:click=...`) and bind directives are NOT props
  — they don't appear in the provided-props map.

Stretch gaps documented:
- Only literal-type matching (string/integer/boolean). Identifiers
  and call expressions skip the type check.
- Every declared field is treated as required (no Option<T> opt-out).
- Full type integration is T135+ per task MUST NOT list.
