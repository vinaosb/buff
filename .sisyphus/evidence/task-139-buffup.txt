1. DESIGN SUMMARY
================================================================================

`buffup` is the Rust implementation of the `rustup` workflow applied to the
Buff language. It downloads pre-built Buff binaries from GitHub Releases
(https://github.com/buff-lang/buff/releases), installs them under
`~/.buff/versions/<ver>/`, and points `~/.buff/bin/buff[.exe]` at the active
version via a symlink (Unix) or copy/junction (Windows fallback).

Subcommands (matches spec L2445-2451):
  - `buffup install <version>` — parse semver → query GitHub Releases API →
    stream gzip tarball → unpack via `flate2::GzDecoder` + `tar::Archive::unpack`.
  - `buffup default <version>` — locate `<ver>/buff[.exe]` → symlink/copy
    `<buff_home>/bin/buff[.exe]` at it. Unix uses real symlinks; Windows
    tries symlink first, falls back to plain copy without privileges.
  - `buffup list` — scan `<buff_home>/versions/`, parse each entry as semver,
    sort ascending, mark the active one with `* (active)`.
  - `buffup update` — NOT YET IMPLEMENTED. Prints actionable build-from-source
    guidance to stderr and returns `BuffupError::NotImplemented`. Self-update
    requires a buffup release channel + in-place binary swap + version manifest
    (deferred to T139 follow-up per out-of-scope list L2456).
  - `buffup --version`, `buffup --help` — clap derive defaults, exit 0.

Path resolution (src/paths.rs):
  - `<buff_home>` = `$BUFFUP_HOME` (test override) OR `dirs::home_dir().join(".buff")`.
  - Versions:    `<buff_home>/versions/<ver>/`
  - Active ptr:  `<buff_home>/bin/buff` (Unix) / `buff.exe` (Windows)

GitHub API client (src/github.rs):
  - Base URL: `$BUFFUP_GITHUB_API` (test override) OR
    `https://api.github.com/repos/buff-lang/buff`.
  - Endpoint: `GET /releases/tags/v<version>` with `User-Agent: buffup` header.
  - Release JSON parsed via serde into {tag_name, tarball_url, zipball_url, assets}.

Graceful failure when Releases don't exist (spec L2461):
  - 404 from GitHub Releases API surfaces a 3-line "Releases don't exist yet"
    message with build-from-source instructions BEFORE returning the error.
  - This is the "USER ACTION" path — until the v1.12 release pipeline ships
    GitHub Releases, `buffup install <ver>` fails cleanly without crashing.

Cross-platform behavior:
  - Unix (cfg(unix)):    std::os::unix::fs::symlink. No privileges needed.
  - Windows (cfg(windows)): symlink_file first, plain copy on EPERM.
    Copy fallback does NOT auto-track reinstalls — user must re-run
    `buffup default <ver>` after reinstalling. Documented in README.md
    and src/commands/default_cmd.rs.
