CLI DESIGN
----------
7 subcommands via clap derive (mirrors buff-lang-cli pattern):
  bufflings list               — Show exercises with [x]/[ ] status per topic
  bufflings start <name>       — Print path, open $EDITOR if set
  bufflings verify <name>       — TODO fast-fail, then `buff check` subprocess
  bufflings verify --all        — Verify all, exit 0 only if all pass
  bufflings progress           — X/Y summary with percentage
  bufflings watch               — notify 6.x file watcher, 200ms debounce, auto-verify on save
  bufflings hint <name>         — Show hint from manifest

VERIFICATION ENGINE
------------------
1. Fast-fail: scan for `// TODO:` lines in source → NotDoneYet (no buff invocation)
2. Run `buff check <path>` subprocess → exit 0 = Solved, non-zero = CompileError(stderr)
3. BuffNotFound when `buff` binary not on PATH (graceful degradation)

DESIGN DECISIONS
----------------
1. NO source dependency on buff-lang-cli. bufflings shells out to `buff` subprocess.
   This keeps bufflings standalone and avoids pulling clap+tokio transitively.

2. Exercise manifest uses TOML [[topics]] array-of-tables pattern (not BTreeMap).
   Each topic has a name + exercises array. Simpler to read, easier to reorder.

3. Solution files use .sol.buff extension (not in a separate solutions/ dir).
   They live next to exercises. T138c uses them for CI gate comparison.

4. Progress file uses ISO-8601 timestamps via std::time (no chrono dependency).
   Keeps the dep surface minimal.

5. No ANSI color crate (crossterm/termcolor/etc). Colors use raw ANSI escapes.
   Matches the "no new deps" mandate.

6. Watch mode spawns a tokio current-thread runtime (matching buff-repl pattern).
   The single-threaded runtime is sufficient for one file watcher.
