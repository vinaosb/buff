Feature Inventory (6 features)
==============================

1. {@html} raw HTML escape hatch
   Syntax:    `{@html raw_trusted_html}`
   AST shape: `RsxNode::RawHtml(RsxRawHtml { expr: String, span: Span })`
   Lexer:     new `BuffHtmlTokenKind::HtmlEscape(String)` token
   Codegen:   `div { dangerous_inner_html: <expr>, data_buffhtml_xss: "{@html} opt-in" }`
   Audit:     runtime marker via `data_buffhtml_xss="..."` HTML attribute
              (visible in DevTools; scrape-able by security tooling).
              prettyplease strips `//` comments inside macro bodies, so the
              marker is an attribute rather than a comment.
   Tests:     lexer × 3, parser × 1, codegen × 2.

2. Spread props
   Syntax:    `<Button {...rest} label: "Override" />`
   AST shape: `RsxAttributeKind::Spread { ident: String }`
   Lexer:     new `BuffHtmlTokenKind::AttrSpread(String)` token (emitted in
              attribute position when `{` is followed by `...ident`)
   Codegen:   `..rest` (Dioxus spread syntax — `..ident`).
   Tests:     lexer × 1, parser × 1, codegen × 2.

3. Named slots
   Syntax:    `<slot name="header" />` (also default `<slot />` unchanged)
   AST shape: `RsxSlot { name: Option<String>, span: Span }` (existing struct
              extended with `name` field; `RsxSlot::named()` ctor added)
   Lexer:     unchanged — emits existing `AttrName("name") AttrEq AttrStrLit`
              inside `<slot>` (already worked; the parser now interprets)
   Parser:    `parse_slot` walks attributes; recognizes only `name="..."`;
              other attrs → "unknown attribute" error; empty name → error;
              non-alpha-starting name → error
   Codegen:   default → `{ children }`; named → `{ <sanitized_name> }`
              (e.g. `<slot name="header" />` → `{ header }`)
              The parent component must declare the matching named-child
              parameter (`fn Comp(children: Element, header: Element)`).
   Tests:     ast-rsx × 1, parser × 4, codegen × 2.

4. Keyed each + ( limitation fix
   Syntax:    `{#each items as item (item.id)}` (the `(key)` is the new form)
   Side-fix:  `(` inside the iterable expression was rejected by the old
              lexer. Now only `(` AFTER the binding is the key form. So
              `{#each items.read() as item}` works (was a hard error before).
   AST shape: `RsxEach { ..., key: Option<String> }` (existing struct
              extended with `key` field)
   Lexer:     `EachOpen` token gains `key: Option<String>` field.
              New helper `find_each_as_boundary()` walks the directive body
              with paren/bracket/string depth tracking — only matches ` as `
              at top level. This fixes the `(`-in-iterable limitation.
              New helper `parse_binding_index_key()` parses the post-`as`
              part: `binding`, `binding, index`, `binding (key)`, or
              `binding, index (key)`.
   Parser:    `parse_each` destructures the new `key` field; passes through.
   Codegen:   `{ items.iter().enumerate().map(|(__buff_idx, item)| {
              let __buff_key = <key_expr>; rsx!{ key: __buff_key, <body> }
              }).collect::<Vec<_>>() }`.
              Uses distinct idents (`__buff_idx` for the positional index,
              `__buff_key` for the user key) to avoid shadowing.
   Tests:     lexer × 5 (3 new + 2 modified), parser × 2, codegen × 2.

5. Two-way binding
   Syntax:    `<input bind:value={name} />` (Svelte-style directive form,
              matching the existing `on:event` convention)
   AST shape: `RsxAttributeKind::Bind { prop: String, signal: String }`
   Lexer:     unchanged — `bind:value` already lexes as a single AttrName
              (the lexer's `read_attr_name` already accepts `:`).
   Parser:    `parse_eq_attribute` checks for `bind:` prefix on the attr
              name and routes to `Bind` instead of `Expression`.
   Codegen:   Controlled-component form:
              `<input value: name, oninput: move |__e| { name.set(__e.value()); } />`.
              Emits two attributes: `value: <signal>` and an `oninput` move
              closure that calls `<signal>.set(__e.value())`. The signal
              must be a `use_signal<String>` (or compatible). The event
              type is left for Rust to infer (cleaner than pinning to
              `Event<FormData>`).
   Tests:     parser × 1, codegen × 2.

6. Await blocks
   Syntax:    `{#await fetchUser(id)} <Spinner /> {:then user}
              <Profile user: {user} /> {:catch err} <Error msg: {err.message} />
              {/await}`
   AST shape: `RsxNode::Await(RsxAwait { fut_expr, fut_span,
              pending_body: Option<Vec<RsxNode>>, then_binding: String,
              then_body: Vec<RsxNode>, catch_binding: Option<String>,
              catch_body: Option<Vec<RsxNode>>, span: Span })`
   Lexer:     new tokens: `AwaitOpen(String)`, `AwaitThen(String)`,
              `AwaitCatch(String)`, `AwaitClose`. Recognized in
              `scan_brace` (await) + `scan_else_directive` (then/catch) +
              `scan_block_close` (/await).
   Parser:    `parse_await` parses the 4-part directive:
              - mandatory `{#await fut_expr}`
              - optional pending body (any nodes)
              - mandatory `{:then binding}` + then body
              - optional `{:catch binding}` + catch body
              - mandatory `{/await}`
              Awaits without `{:then}` are rejected.
   Codegen:   `use_resource` hook pattern:
              `{ let __buff_resource = use_resource(|| async { <fut>.await });
              match __buff_resource.read().clone() {
                ResourceState::Ready(Ok(<binding>)) => rsx!{ <then_body> },
                ResourceState::Ready(Err(<catch_binding>)) => rsx!{ <catch_body> },
                _ => rsx!{ <pending_body or Fragment {}> },
              } }`.
              The full path (`::dioxus::prelude::use_resource`,
              `::dioxus::prelude::ResourceState`) is used to avoid `use *`
              ambiguity in the generated source.
   Note:      Dioxus 0.7's `use_resource` returns `Resource<T>` where reading
              yields a `ResourceState<T, E>` enum. The `match` form is the
              idiomatic one. If the user's future yields a non-Result type,
              they'll get a Rust compile error pointing at the `Err` arm —
              acceptable for T133 (fail-loud at `buff build`).
   Tests:     lexer × 1, parser × 3, codegen × 2.
