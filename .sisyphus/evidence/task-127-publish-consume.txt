ACCEPTANCE MAPPING
================================================================
[x] `buff login` stores credentials
      -> registry_cli_t127::login_stores_token — writes token to
         <BUFF_HOME>/credentials; load-back asserted.
[x] `buff add <pkg>` fetches and adds to buff.toml
      -> registry_cli_t127::login_then_publish_then_add_round_trip —
         resolves pkg via GET /api/v1/resolve, records a
         [registry-dependencies] entry in buff.toml.
[x] `buff publish` uploads package to registry
      -> registry_cli_t127::publish_uploads_tarball — packs src/ into a
         tar, base64-envelopes it, POST /api/v1/publish (Bearer); a
         follow-up GET confirms the stored package.
[x] `buff install <binary>` installs CLI tool
      -> registry_cli_t127::install_downloads_and_unpacks_tarball —
         downloads via GET /api/v1/download and unpacks into
         <BUFF_HOME>/install/<name>/<version>/.
[ ] Consumed package's functions callable  — DEFERRED (honest gap)
      -> `buff add` records the dep and the tarball round-trips intact,
         BUT end-to-end "import + call + build + run" of a consumed
         package is NOT wired: the CLI compiles ONE .buff file at a time
         (README "Examples" note; multi-file/module linking is the same
         v0.5 codegen-only gap). Cross-package linking is post-v1.0 work.
         Not claimed as done.
