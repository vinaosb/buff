# Buff SDK 2.0 — Conventions Specification

**Status:** Accepted (T0 / Buff SDK 2.0 / v1.13 floor)
**Date:** 2026-07-21
**Authors:** Buff Lang Team
**Supersedes:** `.sisyphus/plans/buff-conventions.md` (Buff language syntax conventions; this doc covers the SDK / project-model layer above it)

---

## 0. Purpose

Buff SDK 2.0 is the .NET-Core-style evolution of the Buff developer experience.
It defines **one** way to structure a Buff project, **one** set of attribute
semantics, **one** set of editor expectations, **one** release cadence — so that
every framework written on top of Buff (buff-web, buff-ml, buff-game,
buff-pipeline, buff-dataframe, …) composes consistently and users learn Buff
once.

This document is the canonical reference for the 10 convention categories
introduced in v1.13:

| Cat | Topic | Section |
|---|---|---|
| A | Project & Build | §1 |
| B | Modules & Visibility | §2 |
| C | Scaffolding & Templates | §3 |
| D | Configuration & Environment | §4 |
| E | Documentation | §5 |
| F | Testing | §6 |
| G | Versioning & Compatibility | §7 |
| H | Editor & DX | §8 |
| I | CI/CD | §9 |
| J | Buff SDK Bundle | §10 |

**Scope:** every Buff project shipped via the official templates or
contributed back to the buff-lang org MUST follow these conventions. Downstream
users are free to deviate, but tooling (LSP, `buff check`, `buff doc`, CI
templates) is tuned for projects that follow them.

## 1. Project & Build Conventions (A)

### 1.1 Standard project layout

```
my_app/
├── buff.toml              # project manifest (v2 schema)
├── src/
│   ├── main.buff          # binary entry point (omit for lib template)
│   ├── lib.buff           # library entry point (omit for binary template)
│   ├── modules/           # sub-modules discovered by T1's resolver
│   │   └── user.buff
│   └── prelude.buff       # project prelude (optional; see §2.3)
├── tests/
│   ├── unit/              # tests/unit/*.buff run by `buff test`
│   ├── integration/       # tests/integration/*.buff
│   ├── snapshots/         # insta-style snapshot fixtures
│   └── fixtures/          # static input data
├── examples/              # `buff run examples/<name>.buff` examples
├── benches/               # @bench functions; run by `buff bench` (v1.14+)
├── docs/                  # project-level docs; consumed by `buff doc`
├── .github/workflows/
│   └── ci.yml             # 3-OS CI matrix; see §9
├── .buff/vscode/
│   └── settings.json      # format-on-save + LSP config (see §8)
└── buff.lock              # gitignored; generated by `buff build`
```

**Required:** `buff.toml`, `src/` (with at least one `.buff` file), `tests/`.
**Recommended:** `examples/`, `docs/`, `.github/workflows/ci.yml`.
**Generated:** `buff.lock`, `target/`, `*.rs` (next to source).

### 1.2 Manifest schema (`buff.toml` v2)

`buff.toml` is parsed by `crates/buff-lang-cli/src/config.rs`. v2 is
**additive**: every v1 manifest still parses unchanged. New optional sections:

| Section | Purpose | Owner task |
|---|---|---|
| `[features]` | Named feature flags + `default = [...]` | T0-A1 / T0-B4 |
| `[lints]` | Per-lint severity (`clippy = "deny"` etc.) | T0-A1 |
| `[profile.dev\|release\|bench\|test]` | Per-profile codegen options | T0-A1 / T0-A4 |
| `[prelude]` | Project-wide implicit imports | T0-A1 / T0-B3 |
| `[workspace.dependencies]` / `[workspace.extern]` | Dep inheritance | T0-A3b |
| `[package].stability` | `"experimental"\|"beta"\|"stable"\|"locked"` | T0-G2 |
| `[package].edition = "2026"` | Opt-in to v2-only behaviour | T0-A1 |

A canonical v2 manifest:

```toml
[package]
name = "my_app"
version = "0.1.0"
edition = "2026"
stability = "experimental"

[features]
default = ["logging"]
logging = []
json = ["logging"]

[lints]
clippy = "deny"

[profile.release]
opt-level = 3
lto = true
codegen-units = 1

[prelude]
modules = ["./src/prelude.buff"]
```

### 1.3 Build profiles

`BUFF_PROFILE=<name>` selects the active profile. `--release` is sugar for
`BUFF_PROFILE=release`. Profiles absent from `buff.toml` fall back to:

- `bench` → `release`
- `test`  → `dev`
- `dev`   → rustc built-in defaults
- `release` → rustc built-in defaults + `-C opt-level=3`

### 1.4 Workspaces (A3)

A multi-crate Buff project has a `buff.workspace.toml` at the root:

```toml
[workspace]
members = ["crates/*"]
resolver = "2"

[workspace.dependencies]
serde = "1.0"
buff-web = "0.3"

[workspace.extern]
reqwest = "0.12"
```

Member crates inherit workspace deps via `dep.workspace = true`:

```toml
# crates/api/buff.toml
[package]
name = "api"
version = "0.1.0"

[dependencies]
serde.workspace = true
buff-web.workspace = true
```

This mirrors Cargo's well-loved pattern and prevents version drift across
crates in a monorepo.

## 2. Modules & Visibility (B)

### 2.1 `import` / `export` — same as v0.5

```buff
// src/lib.buff
export func greet(name):
    print("Hello, " + name)

// src/main.buff
import { greet } from "./lib"
greet("world")
```

Two shapes are supported: ES6 (`import { a, b } from "path"`) and module-path
(`import "path"` re-exports everything). See
`crates/buff-lang-ast/src/decl.rs::ImportDecl`.

### 2.2 `@internal` attribute (B2)

A function marked `@internal` is part of the crate's private API. It is
exported so other modules in the same crate can use it, but LSP / docs surface
a warning when it's referenced from outside the declaring crate. **Convention
only for v1.13-v1.17** — compile-time enforcement is deferred to v1.18+.

```buff
@internal
export func helper_only_for_this_crate():
    return 42
```

### 2.3 `[prelude]` section (B3)

The project prelude is a list of module paths in `buff.toml` whose `export`s
become ambient in every source file:

```toml
[prelude]
modules = ["./src/prelude.buff", "./src/logging.buff"]
```

```buff
// src/prelude.buff
export func project_welcome():
    print("Welcome to my_app")

// src/main.buff — NO import needed; project_welcome is ambient
func main():
    project_welcome()
```

The global prelude (`print`, `Vector<T>`, `DateTime`, etc.) remains ambient
regardless of `[prelude]` config.

### 2.4 `@feature(name)` conditional compilation (B4)

Any `export` declaration may carry `@feature(name)`. Codegen emits the decl
only when `name` is in the resolved feature set:

```buff
@feature(logging)
export func debug(msg):
    print("[DEBUG] " + msg)
```

`buff build --features logging,json` enables those features plus anything
they transitively imply. `--no-default-features` disables `[features].default`.
Mirrors Rust `#[cfg(feature = "...")]` and Go build tags.

### 2.5 `index.buff` barrel files (B1)

When a directory contains `index.buff`, importing the directory path
re-exports from `index.buff`:

```buff
// src/modules/index.buff
export { helper } from "./user"
export { format } from "./utils"

// src/main.buff
import { helper, format } from "./modules"   // resolves to index.buff
```

Implemented in T1's resolver.

## 3. Scaffolding & Templates (C)

### 3.1 Built-in templates (C1)

`buff new --template <name>` selects one of 7 built-in templates:

| Template | Description | Entry |
|---|---|---|
| `console` (default) | Runnable binary | `src/main.buff` |
| `lib` | Library crate | `src/lib.buff` |
| `web` | buff-web + buff-template scaffold | `src/main.buff` + http server |
| `ml` | buff-ml + buff-tensor project | `src/main.buff` + tensor demo |
| `game` | buff-game + buff-ecs project | `src/main.buff` + game loop |
| `pipeline` | buff-pipeline + buff-dataframe project | `src/main.buff` + ETL demo |
| `workspace` | Multi-crate workspace skeleton | `buff.workspace.toml` |

Each template ships:
- `buff.toml` (v2, with stability = "experimental")
- `src/main.buff` (or `src/lib.buff` for lib)
- `tests/test_hello.buff`
- `examples/hello.buff`
- `README.md`
- `.github/workflows/ci.yml`
- `.gitignore`
- `.env.example` (for templates that touch env vars)
- `Dockerfile` (console template only; multi-stage builder + slim runtime)

### 3.2 Backward-compat alias flags

The v0.5 `--lib` / `--server` / `--gpu` / `--workspace` flags on `buff new`
continue to work — they alias to the new templates:

| v0.5 flag | v2 template |
|---|---|
| (none) | `console` |
| `--lib` | `lib` |
| `--server` | `console` (with async demo content) |
| `--gpu` | `console` (with `@prefer(gpu)` demo content) |
| `--workspace` | `workspace` |

### 3.3 `buff gen` subcommand (C2)

Reduces boilerplate. Three generators:

| Command | Effect |
|---|---|
| `buff gen module <name>` | Creates `src/modules/<name>.buff` + `tests/unit/test_<name>.buff` |
| `buff gen test <name>` | Creates `tests/unit/<name>.buff` with a stub `@test` fn |
| `buff gen example <name>` | Creates `examples/<name>.buff` with a `func main():` stub |

## 4. Configuration & Environment (D)

### 4.1 `.env` auto-loading (D1)

`buff run` and `buff test` auto-load `.env` from the project root when it
exists **in dev profile only** (i.e. not in release). The prelude's `env()`
helper reads from the loaded environment:

```buff
func main():
    let api_key = env("API_KEY")
    print("Loaded key: " + api_key)
```

### 4.2 `.env.example` convention (D2)

Templates that touch env vars ship `.env.example` (committed) alongside
`.env` (gitignored). `.env.example` documents required keys without leaking
secrets:

```bash
# .env.example
API_KEY=your-api-key-here
DATABASE_URL=postgres://localhost/my_app
```

### 4.3 `buff.config.buff` programmatic config (D3) — **deferred to v1.18+**

An optional build-time Buff script that runs at `buff build` start. Lets
projects compute config dynamically (e.g. detect platform, fetch a token).
Advanced feature; not shipped in v1.13-v1.17.

## 5. Documentation (E)

### 5.1 Doc comments standard (E2)

Buff formalises Rust's two-form doc-comment convention:

- `///` documents the **item** below (function, struct, enum, trait).
- `//!` documents the **enclosing module** (file-level doc).

```buff
//! User-management module.
//!
//! Provides CRUD operations on the User entity.

/// A registered user of the system.
struct User:
    id: Int
    name: String

/// Create a new user with a generated id.
export func create(name):
    return User.new(id: 1, name: name)
```

`buff check` warns on `export` decls without `///` doc comments.

### 5.2 `buff doc` HTML generator (E3) — **scaffold only in v1.13**

The `buff doc` command emits per-crate HTML API docs (Rustdoc-style).
**Rendering is deferred to v1.18+** — v1.13 ships only the command scaffold
so users can wire it into CI today. Running `buff doc` on a project produces
a placeholder `docs/index.html` per crate.

### 5.3 Doc tests (E4) — **deferred to v1.18+**

Extract fenced ` ```buff ` blocks from doc comments and run them as tests via
`buff test --doctest`. Not shipped in v1.13-v1.17.

## 6. Testing (F)

### 6.1 Test layout (F1)

```
tests/
├── unit/           # tests/unit/*.buff — fast, isolated, no I/O
├── integration/    # tests/integration/*.buff — full pipeline, may touch fs
├── snapshots/      # insta-style snapshot fixtures
└── fixtures/       # static input data loaded by tests
```

`buff test` discovers all four directories. Files must end in `.buff`. Test
functions are tagged with `@test` (the existing T35 attribute).

### 6.2 Test attribute standards (F2)

Beyond the existing `@test`, Buff accepts:

| Attribute | Lowers to (Rust) | Effect |
|---|---|---|
| `@test` | `#[test]` | Standard test fn |
| `@bench` | `#[bench]` (via `buff bench`) | Benchmark fn (requires `bench` profile) |
| `@property` | `proptest::property` (via extern) | Property-based test |
| `@should_panic` | `#[should_panic]` | Test fn expected to panic |
| `@ignore` | `#[ignore]` | Test fn skipped by default; run with `--include-ignored` |

```buff
@test
@should_panic
func test_div_by_zero():
    let _ = 1 / 0

@bench
func bench_sort_small():
    let xs = Vector.of(3, 1, 2)
    xs.sort()

@property
fn test_reverse_inverse(xs: Vector<Int>):
    assert(xs.reverse().reverse() == xs)
```

## 7. Versioning & Compatibility (G)

### 7.1 SemVer strict validation (G1)

`buff publish` rejects versions not matching SemVer 2.0
(`MAJOR.MINOR.PATCH` with optional `-prerelease` and `+build`). Reuses the
existing v1.6 registry validation.

### 7.2 Stability badges (G2)

`[package].stability` declares the API stability of a published package:

| Badge | Meaning |
|---|---|
| `experimental` | API in flux; no compatibility guarantee between minor versions |
| `beta` | API mostly settled; minor breakage possible with notice |
| `stable` | SemVer holds; safe to depend on |
| `locked` | Stable + downstream pinned to exact version (`=X.Y.Z`) |

Surfaced in `buff publish`, the registry search results, and package pages.

### 7.3 `@deprecated` attribute (G3)

```buff
@deprecated(since = "2.0", replacement = "new_fn")
export func old_fn():
    return 0
```

`buff check` emits a warning at every call site of a deprecated fn:

```
warning: call to deprecated function 'old_fn'
   --> src/main.buff:5:5
    |
  5 |     old_fn()
    |     ^^^^^^^ since 2.0, use 'new_fn'
```

## 8. Editor & DX (H)

### 8.1 `.buff/vscode/settings.json` convention (H1) — **deferred to v1.18+**

Templates will eventually write a per-project `.buff/vscode/settings.json`
configuring format-on-save + LSP. The VSCode extension from v1.2 already
exists; this just standardises per-project config. **Not shipped in v1.13**;
templates that want it today can write the file manually.

### 8.2 Snippet library (H2) — **deferred to v1.18+**

The VSCode extension gains snippets for `fn`, `match`, `Result<T,E>`,
`Vector<T>`, struct / enum templates. **Deferred to v1.18+.**

### 8.3 Per-crate AGENTS.md

Every Rust crate under `crates/` ships an `AGENTS.md` documenting its
structure, conventions, and "where to look" table. This pattern (formalised
in v1.9) continues for every new crate.

## 9. CI/CD (I)

### 9.1 CI template (I1)

Every template ships `.github/workflows/ci.yml` running on a 3-OS matrix
(ubuntu-latest, windows-latest, macos-latest):

```yaml
name: CI
on: [push, pull_request]
jobs:
  test:
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@master
        with:
          toolchain: 1.95.0
      - run: buff fmt --check
      - run: buff check -D
      - run: buff test
```

### 9.2 Dockerfile template (I2)

The `console` template ships a multi-stage `Dockerfile`:

```dockerfile
FROM ghcr.io/buff-lang/buff:builder AS build
WORKDIR /app
COPY . .
RUN buff build --release

FROM ghcr.io/buff-lang/buff:slim
COPY --from=build /app/target/release/my_app /usr/local/bin/my_app
ENTRYPOINT ["my_app"]
```

`buff:builder` carries rustc + the Buff toolchain; `buff:slim` is a
distroless-style runtime carrying only the Buff runtime shared libs.

### 9.3 `buff release` command (I3) — **scaffold only in v1.13**

`buff release <patch|minor|major>`:

1. Verifies the working tree is clean (`git diff --exit-code`).
2. Bumps `[package].version` in `buff.toml`.
3. Updates `CHANGELOG.md` from a template section.
4. Tags git: `git tag v<X.Y.Z>`.
5. Invokes `buff publish` (T0-G1 SemVer validation runs here).

**v1.13 ships only the command scaffold.** Full CHANGELOG regeneration and
publish integration arrive with v1.14+.

## 10. Buff SDK Bundle (J)

### 10.1 What's bundled vs `buff add`-able

The "Buff SDK 2.0" bundle is the set of crates every new Buff project gets
by default — analogous to .NET's runtime + ASP.NET + EF Core bundle.

**Bundled (implicit, no `buff add` needed):**

- The Buff stdlib (`print`, `Vector<T>`, `Map<K,V>`, `Result<T,E>`,
  `Option<T>`, `DateTime`, `Regex`, `URL`, `Math`, `Filesystem`, `Crypto`,
  `Log`, `Toml`, `Random`, `Base64`, `Hex`, `UUID`, `Csv`, `Yaml`, `Env`,
  `Args`, `Process`, `TCP`, `UDP`, `WebSocket`).
- `buff-web` — HTTP server + router (use via `buff add buff-web` to opt-in
  to web features, but the runtime is bundled).
- `buff-template` — HTML template engine.
- `buff-reactive` — signals + derived values.
- `buff-observe` — structured logging + tracing.

**`buff add`-able (opt-in):**

- `buff-ml` — ML primitives (tensors, layers, optimisers).
- `buff-tensor` — multi-dim ndarray with GPU dispatch.
- `buff-game` — game loop + input + asset pipeline.
- `buff-ecs` — entity-component-system.
- `buff-pipeline` — ETL stages + schedulers.
- `buff-dataframe` — DataFrame + group-by + join.
- `buff-ui-dioxus` — Dioxus UI wrapper (already shipped in v1.8).

### 10.2 Discoverability

`buff search <query>` queries the registry; the SDK bundle is marked with a
`bundled` badge in results so users know they don't need to add it.
