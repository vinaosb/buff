# Buff Playground

A client-side, transpile-only web playground for the [Buff language][buff].
Write `.buff` on the left; see the generated `.rs` on the right. No server,
no rustc, no execution — just the front-end of the compiler (lexer → parser
→ Rust codegen) compiled to WebAssembly.

> Implemented as task [T114][t114] of the
> [post-v1.0 tooling roadmap][plan].

[buff]: https://github.com/buff-lang/buff
[t114]:  https://github.com/buff-lang/buff/blob/master/.sisyphus/plans/buff-post-v10-tooling.md
[plan]:  https://github.com/buff-lang/buff/blob/master/.sisyphus/plans/buff-post-v10-tooling.md

## What it does

| Feature | Notes |
|---|---|
| Left pane: Buff editor | [CodeMirror 5][cm] with Rust-mode highlighting (close-enough for Buff's 25 keywords). Soft tabs (4 spaces — Buff rejects hard tabs in source). |
| Right pane: read-only Rust | Generated by the same `generate_rust()` code path as the host `buff build`. Prettyplease-formatted. |
| 300 ms debounced transpile | Every keystroke schedules a transpile; idle for 300 ms → run. Status pill in the footer shows `idle` / `working` / `ok` / `error`. |
| Inline error display | Lex/parse/codegen errors surface as a crimson footer + pane state, with a `line:col` location. |
| Share by URL | Source is base64-encoded into the URL fragment (`#s=…`), UTF-8-safe. The **share** button copies the URL to the clipboard. Reload restores the editor. |
| Examples | Built-in: `fibonacci`, `olá, buff`, `calculadora`, `error demo`. |
| Zero server | Once `app.js` and `pkg/*.wasm` are fetched, everything runs in the browser. No backend, no accounts, no persistence beyond the URL. |

[cm]: https://codemirror.net/5/

What it **intentionally does NOT do** (per the plan's `Must NOT Have`):

- **No server-side execution** — no rustc in the browser. The `.buff`→`.rs`
  transpile IS the demo. This is the adoption pitch: "painful Rust → clean
  Buff → same performance".
- **No accounts / auth / persistence beyond the URL fragment.**
- **No multi-file support** — single-file transpile only.

## Build

The `pkg/` directory is **generated**, not committed source-controlled
(see `.gitignore`); regenerate it whenever the compiler or the wasm crate
changes.

### Prerequisites

| Tool | Version | Notes |
|---|---|---|
| Rust | 1.95.0 (pinned in `rust-toolchain.toml`) | Workspace toolchain. |
| `wasm32-unknown-unknown` target | installed via `rustup target add wasm32-unknown-unknown` | Already in CI. |
| `wasm-bindgen-cli` | **must match the wasm-bindgen version Cargo resolves** | See "Pinning wasm-bindgen" below. |

On **Windows**, you also need the MSVC environment (the same one the host
build uses — the build scripts for serde_json / syn run on the host even
when targeting wasm32):

```powershell
$env:LIB="C:\BuildTools\VC\Tools\MSVC\14.44.35207\lib\onecore\x64;C:\Program Files (x86)\Windows Kits\10\Lib\10.0.26100.0\um\x64;C:\Program Files (x86)\Windows Kits\10\Lib\10.0.26100.0\ucrt\x64"
$env:INCLUDE="C:\BuildTools\VC\Tools\MSVC\14.44.35207\include;C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\shared;C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\um;C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\ucrt;C:\Program Files (x86)\Windows Kits\10\Include\10.0.26100.0\winrt"
```

### Step-by-step

```bash
# From the repo root.

# 1. (One-time) Add the wasm target if missing.
rustup target add wasm32-unknown-unknown

# 2. (One-time) Install wasm-bindgen-cli at the version Cargo resolved.
#    IMPORTANT: the CLI version MUST byte-match the wasm-bindgen runtime
#    baked into your .wasm. Mismatches produce a warning + empty output.
#    See "Pinning wasm-bindgen" below for the exact procedure.
cargo install wasm-bindgen-cli --version 0.2.126 --locked
#    ↑ replace 0.2.126 with the output of:
#    cargo tree -p buff-playground-wasm --target wasm32-unknown-unknown \
#      | grep '^├── wasm-bindgen v' | head -1

# 3. Build the .wasm artifact (release for size + speed).
cargo build -p buff-playground-wasm --target wasm32-unknown-unknown --release

# 4. Post-process into JS bindings (writes playground/pkg/).
wasm-bindgen \
    --target web \
    --out-dir playground/pkg \
    --out-name buff_playground \
    target/wasm32-unknown-unknown/release/buff_playground_wasm.wasm
```

After step 4, `playground/pkg/` contains the four files listed in the
layout above. The site is ready to serve.

### Pinning `wasm-bindgen` versions

The workspace `[workspace.dependencies] wasm-bindgen = "0.2"` floats within
the `0.2.x` range (the resolver picks the highest compatible — typically
`0.2.126+`). The runtime version baked into the .wasm must byte-match
the `wasm-bindgen-cli` version used to post-process it. Two ways to keep
them in sync:

- **Easiest**: install the CLI at whatever version `cargo tree` reports
  (the snippet in step 2 above).
- **Reproducible**: pin the runtime in `Cargo.toml`:
  ```toml
  wasm-bindgen = { version = "=0.2.95" }
  ```
  …then `cargo install wasm-bindgen-cli --version 0.2.95`. WARNING: this
  can conflict with other workspace members that require a newer
  wasm-bindgen (e.g. `wgpu v26` requires `>=0.2.100`). If the resolver
  rejects the pin, use the "easiest" approach instead.

## Run locally

Any static file server works. Two common options:

```bash
# Option A: Python stdlib (already installed on most dev machines).
cd playground
python -m http.server 8092 --bind 127.0.0.1
# → http://127.0.0.1:8092/

# Option B: Node serve.
npx serve playground -l 8092
```

The `python -m http.server` invocation is what Playwright's `webServer`
hook uses (see `playwright.config.cjs`).

> NOTE: do NOT open `index.html` directly via `file://` — ES module
> imports (`<script type="module">`) and the `.wasm` fetch are blocked
> by CORS under `file://`. You need an HTTP origin.

## Deploy

The site is 100% static (`index.html` + `app.js` + `styles.css` + `pkg/`),
so any static host works. The deliverable for T114 is **local** only;
public deployment is a later user action.

### GitHub Pages

```bash
# From a clean build of playground/pkg/:
cd playground
git checkout gh-pages  # or your branch
cp -r index.html app.js styles.css pkg /tmp/deploy
# …push /tmp/deploy to gh-pages branch…
```

### Netlify / Vercel / Cloudflare Pages

Point the host at the `playground/` directory. Build command:

```bash
cargo build -p buff-playground-wasm --target wasm32-unknown-unknown --release \
  && wasm-bindgen --target web --out-dir playground/pkg \
       --out-name buff_playground \
       target/wasm32-unknown-unknown/release/buff_playground_wasm.wasm
```

Publish directory: `playground/`. No SPA routing needed — there's only one
page and the share state lives in the URL fragment (never sent to the
server).

## Architecture

```
                            .buff source (string)
                                     │
                                     ▼
   ┌─────────────────────────────────────────────────────────┐
   │  playground/app.js (browser, ~9 KB)                      │
   │    CodeMirror editor                                     │
   │    300 ms debounce                                       │
   │    URL fragment encode/decode (UTF-8-safe base64)        │
   │    error/status UI                                       │
   └─────────────────────────┬─────────────────────────────────┘
                             │ transpile(src) → JSON String
                             ▼
   ┌─────────────────────────────────────────────────────────┐
   │  playground/pkg/buff_playground_bg.wasm (~2.3 MB)        │
   │   ┌─────────────────────────────────────────────────┐    │
   │   │  crates/buff-playground-wasm/src/lib.rs          │    │
   │   │    fn transpile(src) -> String {                 │    │
   │   │      tokenize() → parse() → generate_rust()      │    │
   │   │      →  {"ok":true,"rust":"..."}                 │    │
   │   │      OR  {"ok":false,"error":"...","line":N,…}   │    │
   │   │    }                                            │    │
   │   └─────────────────────────────────────────────────┘    │
   │   uses:                                                 │
   │     • buff-lang-lexer (hand-rolled byte scanner)         │
   │     • buff-lang-parser (recursive-descent + Pratt)       │
   │     • buff-lang-codegen-rust (syn/quote/prettyplease)    │
   │     • buff-lang-error (Diagnostic, SourceMap)            │
   │   NOT used (don't compile to wasm32):                    │
   │     • buff-lang-runtime (rayon/wgpu/tokio)               │
   │     • buff-lang-codegen-wgsl                             │
   └─────────────────────────────────────────────────────────┘
```

The wasm crate is a thin wrapper — it depends ONLY on the pure-logic
compiler sub-crates. No runtime, no GPU, no async. This keeps the
bundle small and the page fast.

### Why `--target web` (not `--target no-modules` / `bundler`)?

`--target web` produces a self-contained ES module that works without
a bundler. The trade-off: top-level `await` is required for the wasm
initialization (handled in `app.js` via `await init()`). For a single-page
playground this is the simplest correct choice.

## Browser support

Tested locally on Chromium (Playwright's bundled headless build).
Expected to work on any modern browser that supports:

- WebAssembly ( universally available since 2017)
- ES modules (`<script type="module">`)
- `TextEncoder` / `TextDecoder` / `btoa` / `atob`
- Async clipboard API (for the **share** button — gracefully degrades
  with a status message if blocked)

The T114 plan calls for "Chrome, Firefox, Safari, Edge"; CI runs
Chromium only. Cross-browser smoke-testing is a post-v1.1 follow-up.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `wasm-bindgen` warns "crate was built with version X, but native wasm-bindgen supports up to version Y" | CLI version doesn't match the runtime version baked into the .wasm. | Install the matching CLI: `cargo install wasm-bindgen-cli --version X --locked`. |
| `pkg/` directory is empty after `wasm-bindgen` ran | Same as above — `wasm-bindgen` aborts on version mismatch. | Same fix. |
| `error[E0463]: can't find crate for 'std'` when building | The `wasm32-unknown-unknown` target isn't installed. | `rustup target add wasm32-unknown-unknown`. |
| `LINK : fatal error LNK1104: cannot open file 'msvcrt.lib'` (Windows) | Build scripts run on the host; need MSVC env. | Set `LIB` and `INCLUDE` env vars (see "Prerequisites" above). |
| Page loads but transpile never runs | `app.js` couldn't fetch `pkg/buff_playground_bg.wasm`. | Verify `playground/pkg/` contains all 4 generated files. |
| `import` fails under `file://` | ES modules + wasm need an HTTP origin. | Serve via `python -m http.server 8092` (or any static server). Don't open the file directly. |
